# M7 goduration Extraction Report

## Decision

`goduration` is the first extracted M7 workspace distribution. It is a pure
Python, dependency-free package with no import from gotpl. pygotpl declares
it as a runtime dependency and retains only Sprig input coercion, clocks,
registry names, and compatibility error translation.

The Go-compatible and Python-native surfaces and packaging boundary are
accepted. Some isolated parser operations became slower; those results are
recorded rather than hidden. A duration-heavy end-to-end fixture now provides a
valid current baseline, although no pre-extraction sample exists for a truthful
before/after percentage.

## Public Boundary

The package exports an immutable, ordered, hashable `Duration` value and typed
unit constants. The API includes:

- Go `time.ParseDuration` syntax and `Duration.String` output;
- signed 64-bit nanosecond bounds, checked construction, and Go arithmetic
  wraparound;
- named constructors from nanoseconds through hours;
- Go integer multiplication, division, remainder, bitwise operations, shifts,
  and integer conversion, plus Python-surface duration ratios;
- rounding and truncation with Go boundary and saturation behavior;
- total-unit accessors; and
- explicit `datetime.timedelta` conversion that rejects silent nanosecond loss.

Sprig's permissive coercion and legacy error strings are deliberately not part
of the standalone package API.

The distribution exposes `goduration.go` and `goduration.python`. Top-level
names continue to default to exact Go behavior. The Python surface uses
arbitrary-size integers, exact decimal text parsing, Python-native
float and Decimal behavior, idiomatic exceptions, and explicit conversion to
and from the signed-64-bit Go value.

## Compatibility and TDD Evidence

Development began with failing direct package tests and then a failing Go
oracle test before implementation. The checked-in fixture is generated by a
small Go 1.27.0 program and is verified byte-for-byte by
`scripts/check_goduration_oracle.sh`.

The vectors cover normal and signed values, both microsecond glyphs, composite
units, values above JavaScript's exact integer range, signed 64-bit edges,
malformed input with exact errors, arithmetic overflow, division, remainder,
negation, round, truncate, and saturation. The schema-2 oracle exposed both
Go's integer wraparound and a non-obvious parsing behavior: fractional units
use float64 scaling, so
`0.3333333333333333333h` becomes exactly `1200000000000ns`. The Python
implementation now preserves that rule.

Direct package evidence on CPython 3.14.7:

| Gate | Result |
| --- | ---: |
| Standalone tests | 74 passed |
| Statement coverage | 100% |
| Branch-aware coverage | 100% |
| Ruff | passed |
| Strict Pyright | passed |
| Go oracle regeneration | byte-identical |
| Focused package, Sprig, and conformance tests | 151 passed |

## Packaging Evidence

The root is now a uv workspace with one lock file and `packages/goduration` as
an explicit member. Both distributions have constrained Hatch sdist contents,
and `goduration` has independent PEP 621 metadata, a `src` layout, tests,
documentation, and a `py.typed` marker.

`uv build --all-packages` produced pure-Python sdists and wheels for both
`goduration` and `pygotpl`. Installing those two wheels into an empty CPython
3.14 environment with dependency resolution disabled successfully imported both
packages and rendered a template. Disabling resolution intentionally isolates
the workspace artifact relationship; normal installation still resolves
pygotpl's documented `tzdata` and `tzlocal` requirements.

## Performance Evidence

Measurements used CPython 3.14.7 on macOS arm64. Each micro result is the median
of seven runs of 100,000 operations. The before values were captured immediately
before moving the helpers; the after values use the independent package and
thin adapters.

| Operation | Before ns/op | After ns/op | Change |
| --- | ---: | ---: | ---: |
| Parse composite duration | 1,107 | 1,587 | +43.4% |
| Format composite duration | 428 | 481 | +12.4% |
| Sprig `duration` adapter | 516 | 458 | -11.2% |
| Sprig `durationRound` adapter | 1,046 | 1,878 | +79.5% |

These microbenchmarks make package construction and exact Go fractional parsing
visible, but they do not represent a complete render. The frozen M6
Sprig-function-heavy fixture supplies only a repository-wide noise control:

| Measurement | M6 before | M7 after | Change |
| --- | ---: | ---: | ---: |
| Python median ns/render | 65,692 | 66,784 | +1.66% |
| Go median ns/render | 9,048 | 9,025 | -0.25% |
| Python/Go ratio | 7.28x | 7.41x | +1.8% |

That fixture does not call `duration`, `durationRound`, or the extracted parser.
Its 1.66% difference must not be attributed to `goduration`. The replacement
duration-heavy Go/Python fixture, `sprig_duration_render.json`, produces matching
output and establishes the following valid current baseline:

| Duration-heavy measurement | Median |
| --- | ---: |
| Python | 36,796 ns/render |
| Go | 3,209 ns/render |
| Python / Go | 11.39x |
| Go allocations | 82 allocations/render |
| Go allocated bytes | 1,424 bytes/render |

The corresponding 25-sample Python memory baseline is 3,773 median peak traced
bytes, 1,836 median positive retained bytes, and 30 median retained blocks per
render. These are post-extraction trend baselines rather than before/after
claims.

The independent surface benchmark uses seven samples of 100,000 operations:

| Operation | Go surface ns/op | Python surface ns/op | Python / Go |
| --- | ---: | ---: | ---: |
| Parse | 1,556 | 2,100 | 1.35x |
| Format | 342 | 342 | 1.00x |
| Multiply | 240 | 207 | 0.86x |
| Round | 283 | 198 | 0.70x |

The multiplication case now uses an integer factor on both surfaces. The
former `1.5` case was removed because multiplying a Go `time.Duration` by a
floating-point value is not valid Go behavior; retaining it as a Go-surface
benchmark would have measured an incompatible extension.

The post-extraction Sprig memory baseline uses 25 single-render tracemalloc
samples: 7,544 median peak traced bytes, 3,723 median positive retained bytes,
and 55 median retained blocks. It is a new trend point, not a direct comparison
with Go allocator counters or the M6 multi-operation profile allocation.

The former general fixture remains useful for detecting broad accidental
changes. The new fixture closes the missing post-extraction duration latency
and allocation baseline, but it cannot retroactively create a pre-extraction
render sample. Parser micro-optimization remains an explicit follow-up and will
be judged against this checked-in baseline.
